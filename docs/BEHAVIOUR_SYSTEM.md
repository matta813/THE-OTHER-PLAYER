# Behaviour System

`BehaviourEvent` stores timestamp, type, position, stable target ID, context, response time, previous related event, and metadata. The recorder caps history at 512 meaningful events and supports recent-event inspection and counts.

The model derives bounded metrics from weighted evidence. Each metric exposes value, confidence, sample count, consistency, and last-change reason. Weight decays modestly with samples so one action cannot permanently label the player. `HabitDetector` uses an extensible rule table to turn events into `BehaviourMemory` entries with support/contradiction counts, strength, confidence, last observation, and time decay. One observation cannot authorize a strong adaptive action; contradictory evidence weakens a habit without deleting history.

The slice records locked-door retries and time-separated rechecks, optional inspection during a power request, room entry, terminal returns after physically leaving, stationary waiting, threshold hesitation, delayed requests, completion/response time, and unnecessary toggles. Rapid repeated keypresses still count as retries, but no longer masquerade as a door-recheck or terminal-return habit. Rules for light-before-entry and route preference exist but have no evidence source in this small level yet. F3 exposes the model and memory only in the developer overlay. The internal `BehaviourProfile` format can export/import aggregate metrics and habits for later New Game+ work; it is not surfaced to players.

Chapter 1 adds room visits, camera-feed inspection and reporting, fuse pickup/deposit/transfer, power rerouting/overload attempts, generator and communications actions, and airlock interactions. Camera guidance contributes response-time evidence so fast cooperation can become a repeated habit instead of a one-off label. `ReciprocityModel` separately summarizes help given, requested, delayed/refused and reliably exchanged.
